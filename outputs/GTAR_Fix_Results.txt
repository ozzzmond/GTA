FINDING STATUS AND EVIDENCE

1. Stable identity across renames -- FIXED on web and Android.
   Stable IDs are authoritative; title/name matching cannot transitively join
   different stable IDs. Name-only legacy references still require unique
   resolution. Same-name arrangements with different IDs remain separate.
   Shared fixtures cover both input orders for song and setlist rename
   collisions, charts, and references. With a known baseline the rename
   example retains A/Renamed and B/Original. Unknown-baseline divergent A
   versions stop as a recoverable conflict rather than choosing cloud content.
   Files: syncMerge.ts, SyncDedup.kt, tests/fixtures/sync-contract.json.

2. Unsynced mutations across restart -- FIXED on both platforms.
   Account-scoped durable baseline/pending journals precede upload and local
   replacement. Acknowledgment is saved before apply; baseline advances after
   persistence. Failed/uncertain uploads retain the previous baseline. Replay
   reconciles an interrupted apply or stops on conflicting intervening edits.
   Recovery snapshots retain the inputs. Storage failure stops sync.
   Web persists songs/trash/setlists atomically in gtar_library_v1. Android
   applies through Room's expected-state transaction. Account switches stop
   sync for a library bound to another account; no automatic cross-account
   transfer is attempted. Journals do not contain OAuth tokens.
   Evidence: real useDriveSync failed-upload/remount test, durable journal
   tests for offline edits/deletions, interrupted apply and account isolation,
   Room concurrent-local-edit protection tests, and atomic persistence test.

3. Concurrent setlist changes -- FIXED on both platforms.
   Removed unconditional membership union during reconciliation. Divergent
   setlist edits stop safely, including removal plus rename, addition plus
   rename, different concurrent reorderings, and delete-versus-rename.
   Ordinary one-sided deletions still reconcile. Shared fixture contracts
   exercise both platforms and both cloud input orders.

4. Check/upload race -- FIXED through retained independent revisions.
   Both transports create new appDataFolder files; neither updates or deletes
   existing sync files. Version-qualified parent IDs identify observed
   ancestry. Independent initial and later writes remain separate branches.
   Divergent heads stop; identical retry siblings can be acknowledged together.
   Uncertain upload outcomes require a pull before retrying. Missing revision
   metadata and invalid payloads fail safely. No ETag or preflight-read claim
   of atomic conditional safety is made.
   Recovery exports include raw cloud history and local attempt snapshots.
   After reviewing/reconciling device content, an explicit confirmed Publish
   resolved device library action creates a revision acknowledging observed
   heads while retaining all previous files.
   Evidence: web transport tests and Android RevisionSyncProtocol tests cover
   interleaving, simultaneous creation, uncertain responses, ancestry, and
   explicit reconciliation. Android DriveAppDataClient uses that tested
   protocol with the actual Drive transport. These are simulated network
   tests, not proof of live service behavior.

6. Room migration safety -- FIXED locally; physical upgrade test outstanding.
   exportSchema=true and KSP schema directory configured; generated Room 7
   schema is included under app/schemas. Destructive fallback removed.
   Populated tests exercise supported versions 2 through 7, real migration
   objects and current Room validation, then reopen and verify content,
   ordering, trash, BPM, tags, timestamps and persistent sync IDs. Historical

   Unsupported v1 fails without deleting rows. Recovery policy: preserve the

7. Unresolved references in full backups -- FIXED.
   Full export validates every reference and reports missing/ambiguous entries;
   it does not filter them out. Original input remains unchanged. The backup
   dialog downloads a raw recovery archive when normal export fails; restore
   the original missing song or deliberately repair the setlist before retry.
   Sync recovery exports are also available. Room sync snapshot creation fails
   on impossible missing song references instead of using mapNotNull.
   Evidence: backupResiduals regression rejects export, verifies unchanged
   inputs, restores a missing ID, and round-trips the repaired full backup.

8. Secure Band Sync endpoints -- FIXED.
   One URL parser preserves ws/wss (and maps http/https consistently), explicit
   ports, paths, queries and bracketed IPv6 through setup, reconnect, custom
   leader endpoint and recent-history storage. Default band port remains 8765.
   Explicit default ports :80/:443 remain explicit to keep normalization
   idempotent. Unsupported schemes/credentials/fragments are rejected.
   Evidence: stageLifecycle tests call the real engine and inspect the URL
   passed to WebSocket on initial connection and reconnect.

9. Late wake-lock acquisition -- FIXED.
   Concurrent requests share one pending acquisition. Cleanup/release invalidate
   it; a sentinel arriving later is immediately released. Destroyed controllers
   cannot reacquire. A delayed-acquisition lifecycle test passes.

NOT EXECUTED / REMAINING RISKS
- Live OAuth consent, live Drive HTTP races and Android/web two-device sync.
  These require configured OAuth credentials and device access.
- Physical-device Room upgrade, signed APK installation/certificate verification,
  real fullscreen/wake-lock/display operation, long performance sessions, and
  deployed PWA upgrades. jsdom/Robolectric checks are not those tests.
- Remote GitHub Actions execution and branch protection were not changed/tested.
- Revision and recovery history is intentionally not compacted. Costs grow with
  history; storage exhaustion stops sync instead of pruning recovery data.
- Upgrade all syncing clients. Old releases cannot read the new revision files
  and still have their old mutable-file behavior.
- Same-name records with different stable IDs remain distinct. Reconciliation
  is deliberately conservative and may require manual content review.
- Account switching stops rather than moving or merging the previous account's
  library. Cross-account transfer remains manual.
- Whole-tree lint cleanup remains open (155 errors, 6 warnings).
